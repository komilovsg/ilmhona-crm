# Анализ старой системы ilmhona-crm (lovable.app)

Дата: 2026-10-21. Источник: проход по интерфейсу под менеджером (Душанбе) и инструктором, только чтение.
Персональные данные сюда не попадают — репозиторий публичный.

## Архитектура старой системы

- Фронт: Lovable (React + shadcn/ui + Tailwind), шрифт Inter.
- Вход и роли: Supabase (`profiles`, `user_roles`, `crm_grade_breakdowns`).
- **Все бизнес-данные — 11 листов Google Sheets** через Google Apps Script (`action=batchRead`):
  `LEADS, STUDENTS, COURSES, COHORTS, ENROLLMENTS, PAYMENTS, MARKETING, INSTRUCTORS, ATTENDANCE, GRADES, INSTRUCTOR_PAYMENTS`.
  Весь массив грузится одним запросом при входе; кнопки «Обновить данные» перечитывают его.
- Филиалы: Душанбе, Истаравшан. Аудитории: Lovelace, Jobs, Gates, B-H, Turing, Istaravshan-1, Istaravshan-2.
- Роли: Администратор, Менеджер (привязан к городу), Инструктор. Прав по разделам нет.

## Баги → правило в новой системе

| # | Баг | Правило |
|---|---|---|
| 1 | Постоянная «Ошибка связи с таблицей (200)», ручное «Обновить» | Postgres вместо Sheets, данные всегда актуальны |
| 2 | Похоже, Apps Script отдаёт все данные без авторизации | Каждый запрос — с сессией и проверкой прав |
| 3 | Цифры расходятся: студентов 783 / 931 / 965, выпускников 390 / 400 / 451, потоков 91 / 95 / 100; «Выпускников: 0» на странице студентов | Каждая метрика — одна функция на бэке; тест сверяет дашборд со списками |
| 4 | Студент дважды в одном потоке | `UNIQUE (cohort_id, student_id)` |
| 5 | «Заполненность 0/20, оплатили 22» | Оплата всегда ссылается на зачисление; «оплатили» считается по зачислениям |
| 6 | Время урока 04:35, 22:35–00:05, 04:35–17:00 | Время в Asia/Dushanbe, проверка диапазона и длительности |
| 7 | Две группы в одной аудитории одновременно | Exclusion constraint на пересечение аудитория × время |
| 8 | Период «Июль 2001» | Проверка дат при вводе и импорте |
| 9 | Расходы ЗП = 0 → прибыль завышена | Выплата — отдельная запись; прибыль по фактическим выплатам |
| 10 | Дубли пользователей/инструкторов (кнопка «Синхр.»), имена латиницей и кириллицей | Инструктор = пользователь с ролью; уникальность логина и телефона; слияние дублей при импорте |
| 11 | Поток «Завершён», студенты в нём «Активный» | Статусы зачислений пересчитываются при закрытии потока |
| 12 | Посещаемость 100 % при 1 отмеченном уроке из 13 | Процент от проведённых уроков; неотмеченные показаны отдельно |
| 13 | Трудоустройство в трёх местах | Одна таблица, остальное — представления |
| 14 | У всех лидов ID «L-001» | Генерируемые ID в базе |
| 15 | В имени лида мусор из рекламных форм (эмодзи, названия чужих бизнесов) | Нормализация и пометка «проверить» при импорте |
| 16 | Модалка не закрывается по Esc | Стандартные модальные окна (HeroUI) |
| 17 | «Эффективность 4332 %» — бессмысленная метрика | Доход на инструктора и на студента, без процента |
| 18 | Посещаемость — горизонтальная таблица, неудобно с телефона | Мобильный режим: один урок на экран, отметка тапом |
| 19 | Помощники пользуются аккаунтом админа | Матрица прав по разделам + область (филиал, свои потоки) + журнал действий |

## Кабинет инструктора

- Меню: **Мои потоки**, **Мой кабинет**. Больше ничего.
- «Мои потоки»: карточки потоков, где он инструктор (курс, код, статус, даты, дни, время, аудитория, студентов X/лимит).
- Внутри потока — те же 3 вкладки, что у менеджера: Студенты (+ «Добавить студента»), Посещаемость (✓ / ✗ / причина, «добавить дату вручную», «скачать табель»), Оценки (Д/З 40 + финал 40, посещ. 20 авто).
- Нет: главного экрана «что сегодня» (уроки дня, что не заполнено), оценок за отдельные Д/З, своих выплат.
