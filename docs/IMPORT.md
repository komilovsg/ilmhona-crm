# Перенос данных из старой системы

Источник: снимок `batchRead` старой системы (11 листов Google Sheets), файл `import-data/sheets-YYYYMMDD.json`
(gitignored, права 600). Пользователи и роли старой Supabase не переносятся: суперадмин заводит сотрудников
заново, инструкторы создаются из листа INSTRUCTORS неактивными, активация — временным паролем на 7 дней.

Команда: `python -m app.importer <file> --dry-run` → отчёт; `--apply` → перенос в одной транзакции.
Только CLI (HTTP-маршрута нет). При `ENV=production` `--apply` требует `--confirm-db <имя базы>`.
Отчёты по умолчанию — в `import-data/` в корне репозитория (папка 700, файлы 600). При ошибке печатается
только тип ошибки и место, без содержимого строк. Текст из старой системы чистится как ввод в приложении:
без NUL/управляющих символов, с лимитами длины полей, суммы — не больше 2 знаков после запятой и < 10¹⁰,
числа NaN/Infinity/1e309 считаются пустыми.
Повторный `--apply` на той же базе ничего не дублирует (идемпотентно по `legacy_id`).
Отчёт (`import-data/report-*.md` + `.xlsx`) содержит только счётчики и ID старой системы, без имён и телефонов;
списки «на проверку» — отдельным xlsx с данными, тоже в `import-data/`.

## Общие правила

- Каждая перенесённая строка хранит `legacy_id` (старый ID + лист) в колонке `legacy_ref` (новая миграция, nullable, unique per table).
- Даты: строки вида `Mon May 04 2026 12:00:00 GMT+0500 (Таджикистан)` → разбор с учётом смещения → дата/время Asia/Dushanbe.
  Пустые и вне 2020–2035 → «на проверку».
- Время уроков (`start_time`/`end_time`, вида `Sun Dec 31 1899 07:05:12 GMT+0435`): берётся время суток и сдвигается на **+11:25**
  (калибровка: 07:05→18:30, 05:35→17:00, 08:35→20:00 совпадают с интерфейсом старой системы). Значения от `Sat Dec 30 1899` и всё,
  что после сдвига вне 07:00–22:00 или длительность вне 30–240 мин → поток переносится без расписания, «на проверку» (баг #6).
- Телефоны → нормализация `+992XXXXXXXXX`, исходное значение сохраняется; пустой → «заполнить».
- Имена → та же гигиена, что у лидов (#15): эмодзи, декоративный Unicode, лишние пробелы; исходное значение сохраняется.
- Формулы (`= + - @` в начале) в тексте не исполняются нигде (импорт → БД → экспорт).
- Города: Душанбе, Истаравшан. «Оба» (у курсов) → курс общий. Пустой город → по аудитории/потоку, иначе «на проверку».

## Дубли (баги #4, #10, #14)

В старой системе ID повторяются (студенты ~100, зачисления ~95, оплаты ~45, посещаемость — тысячи строк).
- Студент: ключ = нормализованный телефон, если есть; иначе (нормализованное ФИО + город). Совпадения сливаются, все старые ID → один новый.
- Один телефон, но разные люди (братья/сёстры на телефоне родителя): телефон сливает строки только если ФИО «то же самое» (`same_person`: слова в латинской транслитерации, порядок не важен; хотя бы одно слово совпадает точно и 2·совпало/(слов_а + слов_б) ≥ 0,8; слово от 4 букв совпадает и при расхождении в 1 букву). Иначе это отдельные студенты с общим телефоном, у каждого «Проверить» с причиной «общий телефон — проверить»; зачисления, оплаты и посещаемость находят своего по паре (старый ID, ФИО).
  Одинаковое ФИО без телефона в одном городе → сливается, но в отчёт «проверить слияние».
- Зачисление: ключ = (студент, поток). Повторы сливаются (#4); статус берётся «старший»: выпускник > завершил > активный > отчислен; дата — самая ранняя.
- Оплата: ключ = (зачисление, месяц, сумма, дата, метод). Точные повторы отбрасываются, остальные строки с одинаковым старым ID переносятся как разные оплаты.
- Посещаемость: ключ = (зачисление, дата урока). При конфликте присутствовал побеждает отсутствовал только если есть заметка — иначе последняя строка; число конфликтов — в отчёт.
- Инструктор: ключ = нормализованное ФИО (латиница и кириллица сводятся транслитерацией, #10); дубли ID сливаются.
- Лид: ID генерируются заново (#14); ключ дубля = телефон + дата.

## Листы

| Лист | Куда | Особенности |
|---|---|---|
| COURSES | course | `city=Оба` → общий; `level` в название не добавлять; цена/мес, длительность |
| INSTRUCTORS | app_user (роль Инструктор, неактивен) | ставка `salary_per_month` → `default_rate` (значение 1 → «на проверку»); статус Удалён → не переносить |
| COHORTS | cohort + lessons | строки без ID и `Удалён` — не переносить; `Отменён` → отменён; курс по `course_id`, иначе по префиксу `course_name` (до « (Mon)»); аудитории: `Istaravshan-2`=`Истаравшан-2`, `Работа` → без аудитории + «на проверку»; `schedule` Пн/Ср/Пт / Вт/Чт/Сб; `cost` → price_month (пусто → цена курса); `max_students` → capacity; `enrolled_count` игнорировать (#3); уроки генерируются из расписания; статус потока пересчитывается по датам (#20) |
| STUDENTS | student | см. дубли; статус пересчитывается из зачислений (в старой все «Активный»); `registration_date` → created_at |
| ENROLLMENTS | enrollment + grade | статусы Активный/Завершил/Отчислен/Ожидает(→активный); оценки: `final_score` = итог; строка `score:A\|B\|C` (в колонке `employed_3m` или безымянной) = посещ./Д/З/финал по шкале старой системы → пересчитать в Д/З 0–40 и финал 0–40 пропорционально; если есть только итог — Д/З и финал пусты, итог в отчёт; `certificate_issued` с «score:» — это не сертификат |
| PAYMENTS | payment | `verified=Да` → подтверждено; `Помесячно` → month_no; `За весь курс`/`Предоплата` → month 1 + пометка в note; метод Alif/Payvand/Наличные; оплата без зачисления → «на проверку», не переносить (#5) |
| ATTENDANCE | attendance | урок ищется по (поток, дата); нет урока → создать ручной урок в эту дату (без аудитории); статус пустой → не переносить; отметки на зачисления «отчислен» переносить (история) |
| GRADES | grade | 3 строки — учесть, если зачисление найдено, иначе отчёт |
| MARKETING | campaign | `Facebook Ads`; бюджет; лиды/зачислено/CPL/CAC/конверсия НЕ переносить (повреждены — даты вместо чисел) — считаются заново; кампании «тест» → «на проверку» |
| LEADS | lead | статусы: client_status Новый/Заинтересован/Отказ, «Оплатил» → записан; call_status «Новый» → не звонили; источник «Платный» → Facebook (реклама), «Электронная почта» → другое + пометка |
| INSTRUCTOR_PAYMENTS | instructor_payout | **колонки сдвинуты на одну**: `instructor_id` содержит ID потока, `cohort_id` — ФИО инструктора, `month` — сумму, `year` — дату выплаты. Разбор со сдвигом, сверка: поток существует и ФИО совпадает с инструктором потока; иначе «на проверку» |

## Отчёт dry-run (что увидит руководство)

По каждому листу: прочитано / перенесено / слито дублей / отброшено (почему) / на проверку.
Сверка после переноса: число студентов, активных зачислений, сумма подтверждённых оплат, число выпускников —
новые цифры из `app/metrics` рядом со старыми из интерфейса старой системы (студентов 783/931/965, выпускников 390/400/451)
с объяснением расхождений.

## Как реализовано (`app/importer`)

- Старые ID повторяются у разных людей (студенты, зачисления), поэтому ссылка идёт по паре (ID, ФИО), а `legacy_ref` = `ЛИСТ:старый-ID~хэш ключа`. Хэш нужен, чтобы два человека с одним ID получили разные ссылки.
- Таблицы с `legacy_ref`: room, course, app_user, cohort, lesson, student, enrollment, payment, instructor_payout, campaign, lead. У attendance и grade ключ — составной PK (урок/зачисление), повторный перенос их не дублирует.
- Строка без `legacy_ref` не меняется и не удаляется; курс/аудитория с тем же названием, созданные вручную, используются как есть.
- Колонки `room_id`, расписание у потока обязательны, поэтому: поток без аудитории (или с занятой, #7) получает свою аудиторию «Без аудитории (G-NNN)»; поток с непригодным временем получает Пн/Ср/Пт 09:00–10:30 без созданных уроков и строку «на проверку».
- Курс потока, которого нет в COURSES, создаётся из названия потока (строка «на проверку»: проверить цену и длительность).
- Итоговый балл без разбивки: Д/З и финал пусты; зачисление завершённого потока с итогом ≥ 70 становится «выпускник» (статус зафиксирован вручную, т.к. разбивки нет). Остальные — через общий путь закрытия потока (#11).
- Присутствовал побеждает отсутствовал, только если у строки «присутствовал» есть заметка; иначе побеждает последняя строка.
- Выплата инструктору: период = n-й месяц потока (колонка со сдвигом), способ неизвестен → «наличные» + пометка.
- Один `import.apply` в журнале на запуск `--apply`.
- Флаги «Проверить» (миграция `0010_review`): `needs_review` + `review_reason` у студента и зачисления (нет телефона, проверить слияние, общий телефон, восстановлено из оплаты, курс создан из названия потока, нет расписания); менеджер снимает флаг (версия + журнал). `enrollment.legacy_total` хранит итог старой системы без разбивки, выпускники показывают его с пометкой «итог из старой системы», пока нет настоящих оценок.
